# 重载下的分级保护、使能归零与提速（未发布，分支 feat/graded-protection）

基线：`main` 的 0.3.2（`87fee14`）。本轮只做了无硬件的软件修改和离线测试，**未连接电机、未通电、未置零、未保存参数**。

| 问题 | 原因 | 修改 |
| --- | --- | --- |
| 云台挂载相机后，轻微外界扰动就让两轴全部失能 | `control_gap`（间隔 >0.1 s）、`feedback_stale`（反馈龄 >0.1 s）、`no_progress`、`hold_oscillation` 都直接失能，没有分级 | 改为 0 正常/1 扰动/2 降级/3 故障四级，见 SDK 说明§4.2。新增 `degraded` 相位和 `snapshot.level`；只有严重情况才失能 |
| 跟踪慢 | 软件参考 30°/s、360°/s²，电机 5 RPM、加速度 1 转/s²，参考超前 9°，滤波偏慢 | 软件参考 90°/s、720°/s²；`response_hz` 8→15、`min_cutoff_hz` 3→6；参考超前 9°→18°；电机侧 `travel_rpm` 5→15、`accel` 1→2；单次反馈预算 40→80 ms |
| 使能后保持原位而不是归 0 | `DEFAULT_HOLD_POSITION` 为 (0°, 35°)，不是已存零位 | 改为 (0°, 0°)；`HeadController.enable()` 在实测位姿使能后沿平滑轨迹回到已存零位，低层 `Gimbal2Dof.enable()` 仍原位保持 |

## 分级保护

- **1 扰动**：不失能、不改相位。暂停本周期，保持上一条指令，轨迹从当前指令重新同步。
- **2 降级**：保持使能，停止推进。无进展时把指令一次性拉回实测位姿，误差 <3° 并稳定 0.3 s 后自动恢复原动作。
- **3 严重**：停止下发并请求两轴失能，需 `reset_fault()`。触发：反馈丢失 ≥0.5 s、间隔 ≥1 s、降级 ≥5 s、30 s 内 ≥6 次 1/2 级事件、写失败、反馈非法、点到点超时、轨迹异常。

## 离线验证

61 项 Python 测试通过（含 Qt offscreen、控制器、伪串口和原生库）；原生 C++ 的协议、SDK API、串口日志检查通过。阻塞写入故障注入（`test_fault_paths`，需要链接器 `--wrap`）本轮未重跑，该部分代码未改动。

## 未验证与风险

- 提速只在模拟里验证。重载下电机能否跟上 90°/s、15 RPM 和 720°/s² 必须实机验证；参考超前放大到 18° 也会让堵转时电机顶得更用力。
- 无进展时把指令拉回实测，在 pitch 抬头负载下如果电机本身托不住，可能随下垂一起下移；这个行为需要现场观察。
- 每个控制周期仍包含两轴读取和两次 8 ms 写间隔，约 25 ms，没有改动，周期上限约 40 Hz。
- wheel 未重建（本环境没有 CMake）。
