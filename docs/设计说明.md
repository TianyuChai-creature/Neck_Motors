# 设计说明（v4.0 两层架构）

目标：让上层（Quest 跟随、UI、脚本）一行 `neck.set_target(yaw, pitch)` 就能安全驱动 F32C 双轴云台；硬件细节与安全逻辑各自只在一处。**纯 Python 标准库**，无 C++、无相机、无第三方依赖。

## 1. 分层与文件协作

```
 你的程序 / tools/ui.py / tools/tune.py
        │  set_target / move_to / tick / enable / disable          ← 只认角度和 phase
        ▼
┌──────────────────────────  neck.control  ────────────────────────────┐
│ neck.py        Neck：唯一入口，状态机 phase，编排每个 tick           │
│ trajectory.py  Trajectory：纯数学，目标→限幅/限速/限加速的下一条指令 │
│ supervisor.py  Supervisor：纯判断，分级保护 level 0/1/2/3            │
└───────────────────────────────┬───────────────────────────────────────┘
                                │  Driver 契约：enable / set / read / disable / close / state
                                ▼
┌──────────────────────────  neck.driver  ─────────────────────────────┐
│ device.py    Driver：两轴、状态 DriverState、串口扫描、失败回滚      │
│ motor.py     Motor：单轴命令间隔 8 ms、查询 25 ms×2 重试             │
│ protocol.py  帧打包/解析、BCC、角度折叠到 [-180,180)                 │
│ port.py      termios 串口：带绝对截止时间的读写、十六进制日志        │
│ types.py     Pose / Gains / DriverConfig / DriverState / DriverError │
└───────────────────────────────┬───────────────────────────────────────┘
                                ▼  TTL 115200，yaw=ID1，pitch=ID2，无 ACK
```

依赖方向只能向下：`control` 只用 `Driver` 的 6 个成员（`tests/fakes.py:FakeDriver` 以同一契约替身，`tests/driver_contract.py` 让真 Driver 与 FakeDriver 跑同一套契约测试）。Supervisor 和 Trajectory 不做 I/O、不读时钟，时间由 Neck 传入，所以可以在测试里精确重放。

## 2. 公共 API

```python
from neck.driver import Driver, DriverConfig
from neck.control import Neck

with Neck(Driver.open()) as neck:          # Driver.open() 自动扫描两个 ID 都应答的串口
    neck.enable()                           # 实测位姿使能，然后平滑回已存零位 (0, 0)
    while running:
        neck.set_target(yaw, pitch)         # 新目标，最新者胜；带 at= 可标注到达时刻
        snap = neck.tick()                  # 每 ~20–33 ms 调一次，同一线程
```

| 对象 | 成员 | 说明 |
| --- | --- | --- |
| `Driver` | `open(config=None)` / `enable(yaw, pitch)` / `set(yaw\|None, pitch\|None)` / `set_zero()` / `save()` / `read(timeout=0.1)` / `disable()` / `close()` / `state` | 层 1。`set` 的 None 表示该轴不动；`read` 返回 `Pose`，角度折在 −180…180 |
| `Neck` | `enable()` / `disable()` / `set_zero()` / `set_target(yaw, pitch, at=None)` / `move_to(yaw, pitch, timeout=None)` / `hold()` / `tick(may_send=None)` / `snapshot` / `enabled` / `reset_fault()` / `close()` | 层 2。`move_to` 点对点，不过期；`set_target` 实时目标，0.2 s 无更新 → `stale` |
| `Snapshot` | `phase, level, reason, measured, command, target, feedback_age_s` | 每次 `tick()` 返回 |
| `NeckError` | `reason, snapshot, cleanup_error` | 故障（level 3）或非法操作；`cleanup_error` 非空表示失能请求也没发出去 |

## 3. 一个 tick 做什么（伪代码）

```
tick(may_send):
    if 距上次 tick > max_gap(0.1 s):            # 调用方卡顿
        level 1（< 1 s）或 level 3（≥ 1 s）；指令从最后一条重新起算
    try: measured = driver.read(0.08 s)
    except DriverError:                          # 读失败，age = 上次成功反馈的年龄
        age ≥ 0.5 s → level 3；age ≥ 0.1 s → level 2；否则 level 1；return
    if 本次读取耗时使反馈已老（≥ 0.1 s）: level 1; return
    if phase == degraded: 只等待稳定；稳定 0.3 s 后恢复原 phase
    finding = supervisor.watch(measured, command, goal)   # 停滞/摆动/误差/升级计数
    if finding.level == 2: return
    if may_send 返回 False: phase = stale; return
    candidate = trajectory.step(now)             # 限位 → 限速 90°/s → 限加速 720°/s² → 平滑
    if 指令领先实测 > 18°: 暂停推进，等反馈（reason = waiting_for_feedback）
    driver.set(变化的轴)                          # 变化 < 0.1° 的轴不发
```

## 4. 状态

**DriverState**（层 1，只描述电机）：`CLOSED`（端口已释放，失能已发）→ `OPEN`（扭矩关）→ `ARMED`（扭矩开，只有此时 `set` 可用）；失能帧没发出去 → `UNKNOWN`（扭矩可能还开着，只能重试 `disable()`）。

**Neck.phase**（层 2，描述“在干什么”）：

```
off ──enable()──▶ hold ──move_to──▶ moving ──到位──▶ hold
                    ▲                 │
                    │            set_target
                    │                 ▼
                    └──hold()/过期──  following ──输入过期/may_send 假──▶ stale
任意使能态 ──level 2──▶ degraded ──稳定 0.3 s──▶ 原 phase
任意使能态 ──level 3──▶ fault（失能 + 锁存）──disable 成功 + reset_fault()──▶ off
```

## 5. 分级保护

| level | 触发（默认值见 `ProtectionConfig`） | 动作 |
| --- | --- | --- |
| 1 扰动 | tick 间隔 0.1–1 s；一次读失败但反馈仍新（< 0.1 s）；读取过慢；保持位振荡（1 s 内摆幅 > 1°） | 本 tick 暂停，不失能；多数计入升级窗口 |
| 2 降级 | 反馈老于 0.1 s 且读失败；某轴误差 > 6° 且 1.5 s 内几乎不动（停滞） | 保持使能，停止推进，把指令拉回实测位姿一次，等误差 < 3° 稳定 0.3 s 后恢复原 phase |
| 3 故障 | 反馈丢失 ≥ 0.5 s；tick 间隔 ≥ 1 s；级 2 持续 ≥ 5 s；30 s 内 6 次级 1/2 事件；移动超时 15 s；写失败；轨迹异常 | 失能并锁存，抛 `NeckError`；恢复需 `disable()` 成功后显式 `reset_fault()` |

只以**实测到位**判定移动完成；不再因“误差大小”直接失能。

## 6. 默认参数

| 项 | 值 |
| --- | --- |
| 限位 | pitch −180°…45°（只截断新目标，不判断反馈）；yaw ±60° |
| 速度 / 加速度（软件） | 90°/s / 720°/s²，响应带宽 15 Hz（≤ 20） |
| 电机速度 / 加速度 | 15 RPM / 2 rev/s² |
| PI（速度 KP/KI，位置 KP/KI） | yaw 40/4、42/0；pitch 10/4、40/0 |
| 总线 | 115200；命令间隔 8 ms；查询 25 ms × 2；两轴读取共享 deadline |
| 位置模式 | `0004` 单圈直通 |

**为什么用 0004**：多圈模式以上电位置为 0°，与 flash 里手动写入的零位不一致；单圈直通适合主机已生成平滑轨迹的高频目标，电机不再二次规划。手册未说明直通模式下 `speed_rpm`/`accel` 是否起作用，需台架确认。

## 7. 人闸与未验证项

- 使能、置零、改 PID、保存参数不由智能体通电实测。
- 写零位（`Neck.set_zero()` → `Driver.set_zero()` + `Driver.save()`）：只在失能或 `hold` 且指令与实测相差 ≤ 1° 时可用，两轴一起。使能时每个电机在自己的零点帧（`0x0A`）之后的下一帧立刻改瞄 0°，避免追旧目标；随后读回两轴须在 ±0.5° 内，否则失能并报 `zero_verify_failed`；通过后才发保存帧（`0x08`，会把加速度等当前参数一并写入 flash）。保存失败只报 `zero_not_saved`，不失能。手册没说零点命令是否改变电机内部目标，**写零瞬间是否会冲需台架确认**，第一次请偏离零位约 2° 再试。
- 全部为**离线测试**（pty 假总线 + FakeDriver）；未实机验证：提速到 90°/s、直通模式下 speed/accel 是否生效、拉回指令后抬头负载下的行为、yaw 全范围在不同 pitch 姿态下的表现。
- 串口断线/超时、写失败、失能失败的分支都有测试，但硬件上的真实表现仍以台架为准。
