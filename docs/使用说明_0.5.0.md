# F32C 颈部控制 · 使用说明（0.5.0）

> 此文档对应 0.5.0。当前版本见 [`使用说明_0.6.0.md`](使用说明_0.6.0.md)。

适用包：`f32c_neck_motors-0.5.0-py3-none-any.whl`  
适用系统：Linux、Python ≥ 3.10（串口使用标准库 `termios`）

0.5.0 是简化核心版本：`protocol.py` 负责帧，`link.py` 负责非阻塞串口，`neck.py` 负责 100 Hz 跟随、使能/失能和置零。wheel 只包含这三个模块和 `types.py`，不包含旧 `neck.driver` / `neck.control`。

## 1. 安装

```bash
pip install wheel/f32c_neck_motors-0.5.0-py3-none-any.whl
```

核心包没有第三方依赖。面板工具需要源码仓库里的 `tools/ui.py` 和 PySide6-Essentials：

```bash
python3 -m pip install -r tools/requirements.txt
python3 tools/ui.py /dev/ttyACM0
```

## 2. 接线与权限

- 电机供电 **8–15 V**，最大工作电流 **1.5 A**，TTL 电平 **3.3 V**。
- USB-TTL 与电机电源必须共地，波特率 **115200、8N1**。
- 默认 **yaw = ID 1**，**pitch = ID 2**；零位保存在电机 flash。
- 当前用户需要串口读写权限（通常在 `dialout` 组）：

```bash
sudo usermod -aG dialout "$USER"   # 重新登录生效
```

不传串口时会扫描 `/dev/serial/by-id/*`、`/dev/ttyACM*`、`/dev/ttyUSB*`，只发查询，选中两个 ID 都应答的口。

## 3. 最小代码

```python
from neck import Neck, NeckConfig

with Neck(NeckConfig(port=None)) as neck:   # None: 自动扫描；也可写 "/dev/ttyACM0"
    result = neck.enable(home=True)         # 以实测位姿使能，再平滑回已存零位
    if not result.ok:
        raise RuntimeError(result.message)

    neck.set_target(20.0, 10.0)             # yaw, pitch；最新目标胜出
    status = neck.status                    # enabled / link_ok / measured / command / reason

    zero = neck.zero(save=True)             # 两轴置零并写 flash
    if not zero.ok:
        print("zero:", zero.error)
```

`with` 进入时启动控制线程，退出时尝试两轴失能并关闭串口。`Neck` 不使用后台线程之外的定时器；`set_target()` 可从 Qt、Quest 回调或任意线程调用。

## 4. UI

```bash
.venv/bin/python tools/ui.py /dev/ttyACM0
```

- 启动时连接电机，初始**未使能**，`status.torque` 为“硬件状态未知”。
- **使能并到零位**：以实测位姿使能，然后平滑回到已存零位；会运动，先确认活动空间。
- **滑条**：使能后每 33 ms 发送一次目标，和上游跟随走同一条路径。
- **暂停输入**：停止发送目标；约 0.2 s 后进入 `input_idle`，保持位置，不故障。
- **写零位（两轴）**：暂停输入，确认后发送零点帧、读回校验、再保存到 flash。不可撤销。
- 关闭窗口会停止控制线程、尝试失能，并在日志旁写 `.close.json`。

## 5. API 摘要

### `NeckConfig`

常用字段：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `port` | `None` | `None` 自动扫描，或显式 `/dev/ttyACM0` |
| `baud` | `115200` | 9600 / 57600 / 115200 |
| `yaw_id` / `pitch_id` | `1` / `2` | 电机地址 |
| `yaw_limits` | `(-60, 60)` | 新目标限位 |
| `pitch_limits` | `(-180, 45)` | 新目标限位 |
| `max_speed` | `90` | deg/s；`None` = 解除软件速度钳位 |
| `max_accel` | `1440` | deg/s²；`None` = 解除软件加速度钳位 |
| `response_hz` | `20` | 二阶跟随响应；解除钳位后仍由它决定平滑度 |
| `control_period` | `0.01` | 100 Hz |
| `frame_gap` | `0.0015` | 帧间隔，手册约 1 ms |
| `feedback_period` | `0.01` | 交替查询两轴，约 50 Hz/轴 |
| `input_timeout` | `0.2` | 超过则 `input_idle`，保持 |
| `feedback_timeout` | `0.1` | 超过则 `feedback_stale`，保持 |
| `max_lead` / `lead_timeout` | `20` / `0.3` | 指令领先实测过多时冻结；`max_lead=None` 关闭 |
| `on_link_loss` | `"hold"` | `"hold"` 或 `"disable"` |
| `disable_after` | `0.5` | 仅 `"disable"` 时生效 |
| `zero_tolerance` | `0.5` | 置零读回容差 |

### `Neck`

| 方法/属性 | 说明 |
| --- | --- |
| `enable(home=False)` | 返回 `CommandResult`；`home=True` 回到已存零位 |
| `disable()` | 返回 `CommandResult`；`torque` 可能是 `on/off/unknown` |
| `set_target(yaw, pitch, at=None)` | 最新目标胜出，线程安全 |
| `zero(save=True, require_stationary=True)` | 返回 `ZeroResult` |
| `status` | 返回 `Status` |
| `start()` / `close()` | 启动/停止控制线程；`close()` 会尝试失能 |
| `enabled` | 是否已发出使能请求 |

### `Status`

`enabled`、`link_ok`、`torque`、`target`、`command`、`measured`、`feedback_age`、`input_age`、`reason`、`tx_errors`、`rx_errors`、`last_error`。

`reason` 的常用值：

- `""`：正常跟随
- `input_idle`：超过 `input_timeout` 没有新目标，保持最后指令
- `feedback_stale`：反馈过期，保持最后指令
- `lead_guard`：指令领先实测超过 `max_lead`，暂停推进
- `link_lost`：配置为 `on_link_loss="disable"` 时的链路丢失
- `zero_saved` / `zero_set` / `zero_unverified`：置零结果

`torque` 只表示“请求已发/硬件未知”，不是电机确认。

## 6. 默认行为

- 控制线程 100 Hz，两轴目标帧按 1.5 ms 间隔调度；目标帧每 tick 更新，不排队积压。
- 二阶临界阻尼跟随，默认响应 20 Hz；限速 90°/s、限加速 1440°/s²。
- 输出按协议 0.1° 量化。
- 使能时先失能、写 PI、逐轴使能、选单圈直通 `0004`、设速度/加速度、发当前位姿目标。
- 默认限位只截断新目标，不用反馈做边界诊断。

### 解除软件速度/加速度限制

0.5.0 起 `max_speed`、`max_accel` 可以设为 `None`，`max_lead` 也可以设为 `None` 关闭领先保护：

```python
cfg = NeckConfig(
    max_speed=None,       # 不再钳制速度
    max_accel=None,       # 不再钳制加速度
    max_lead=None,        # 不再因指令领先实测过多而冻结
    response_hz=20.0,     # 二阶跟随仍保留；想更硬可逐步提高
)
```

注意：

- 解除的是软件钳位，二阶跟随和 `response_hz` 仍在。想更激进，先把 `response_hz` 从 20 提到 30 左右并实测；100 Hz 控制周期下不建议盲目追高。
- 电机侧 `speed_rpm` / `accel` 仍会在使能时下发。直通模式是否实际使用它们，手册没有明确说明，需要台架确认；如果生效，也要按机械能力调整。
- `max_speed=None` / `max_accel=None` 会让目标更接近“直接跟随”，可能撞到机械限位或触发过流保护。第一次先小角度、小范围试，不要直接上全速；`max_lead=None` 也意味着失去最后一层软件防跑飞保护。
- 限位 `yaw_limits` / `pitch_limits` 仍然生效，不受影响。

## 7. 失败与安全

| 事件 | 默认行为 |
| --- | --- |
| 输入过期 | 冻结目标，保持使能；新目标到达自动继续 |
| 反馈过期 | 冻结目标，保持使能；反馈恢复自动继续 |
| 写失败 | 下一 tick 重试；持续失败时冻结推进 |
| 跟随误差过大 | `lead_guard` 冻结推进，等实测追上 |
| 链路丢失 | 默认 `hold`；设置 `on_link_loss="disable"` 可在 `disable_after` 后失能 |
| 置零校验失败 | 返回 `ZeroResult`，目标固定在 0°，不追旧目标 |
| 置零帧写失败且已使能 | 尝试两轴失能；若失能请求也失败，`torque="unknown"` |

注意：F32C 没有主机心跳看门狗。主机崩溃或串口断开时，电机仍可能保持最后目标；软件不能替代硬件急停/断电。pitch 轴有重力负载时，默认 `hold` 通常比直接失能更安全，具体按机械结构确认。

## 8. 置零与 flash

1. 读取两轴新鲜角度。
2. 已使能时要求 `|command - measured| ≤ 1°`，否则返回 `not settled`。
3. 两轴发送 `0x0A`，把当前位置写成 0°。
4. 已使能时立刻发送 0° 目标，避免追旧目标。
5. 读回，要求两轴 `|angle| ≤ 0.5°`。
6. 两轴发送 `0x08` 保存参数到 flash。
7. 返回 `ZeroResult(ok, zeroed, verified, saved, measured, error)`。

保存帧没有 ACK；软件只能确认保存请求已写出。要确认掉电保持，请断电重启后再读一次。第一次真机使用建议先偏离零位约 2° 再试。

## 9. 测试与未验证项

```bash
.venv/bin/python -m unittest discover -s tests -t .
```

当前离线测试覆盖协议黄金帧、非阻塞串口、假总线、跟随/限幅、输入过期、反馈过期、链路丢失、置零成功/失败、UI offscreen。

尚未实机验收：

- 100 Hz 循环抖动与 1.5 ms 帧间隔（如果 BCC 错误，先把 `frame_gap` 调到 2 ms）；
- 15 RPM、90°/s、1440°/s² 下的跟随误差和过冲；
- 直通模式下 speed/accel 是否实际生效；
- 置零读回、断电保持；
- 断线默认保持策略与机械重力负载是否匹配。

## 10. 旧版本

`wheel/f32c_neck_motors-0.4.0-py3-none-any.whl` 是旧 `neck.driver` / `neck.control` 两层实现，没有 `NeckConfig`、`SerialLink`、新 `Neck` API。0.5.0 wheel 只包含新核心；源码仓库里的旧层仅供 `tune.py`、`load_compare.py`、`replay.py` 和回归测试使用。
