# 固定负载整定记录 · 2026-10-12

以下是发布 0.2.1 时的实测记录：整套整定尚未完成，pitch 候选通过一轮多位置验证，yaw 尚未满足用户要求的 −60°～60°；当时未替换默认 PI。随后用户明确选择先使用当前组合，0.2.2 的采用说明见本文末尾。未置零或保存电机参数。

## 现场约定与验收

- 按用户最新约定：pitch 增大低头、减小抬头；yaw 增大为第一人称左转、减小右转。沿用 yaw=ID 1、pitch=ID 2。
- 固定当前摄像头和线缆负载；用户确认线缆有余量，仅提供弹性阻力。
- pitch 指令上限 40°，低头实体极限约 43°；初始失能姿态可能高于 40°，仅先向内退回，正式试验反馈超过 40° 会中止。
- yaw 目标需覆盖 −60°～60°。保持峰峰值 ≤0.6°、保持静差和偏置阶跃误差 ≤1°，返回 ±1° 并持续 0.5 秒的恢复时间 ≤2 秒。
- 自动刺激是位置阶跃；未施加或测量真实外力，不能据此提供绝对扭转刚度或外力冲击恢复结果。

## 抖动现象及调节效果

旧 pitch 候选（速度 15/8、位置 60/0）在自动试验中，目标保持 0° 时反馈出现 +2.5° 至 −5.3° 的摆动，记录到的峰峰值为 7.8°，超过 5° 跟随误差保护后失能。原始记录：`logs/autotune_20261012_101119_5vjq1bvs/`。这属于目标停止后反馈仍摆动的现象，不能用单点到位或较小静差判定稳定。

将 pitch 速度 KP 提至 30，保持速度 KI=8、位置 PI=60/0，使用 5°/s 目标斜坡重新验证。保持振荡明显减小，14 个双向阶跃指标全部通过；这是在本轮条件下有效的候选，尚未证明所有速度、其它轴姿态或长时间工况均稳定。

## 本轮源码修正与 UI

- 原启动流程在加速度和 PI 配置完后才下发保持位置，期间旧目标可能驱动电机。现改为逐轴 enable → mode → speed → 初始目标 → accel/PI，`enable()` 在使能前读位置；新增 C/C++/Python `enable_at()`，允许工具在启动阶段明确约束 pitch 目标。使能和目标之间仍存在串口间隔，不能保证零瞬态运动。
- 自动斜坡仅对变化轴发送目标，与 UI 的逐轴更新方式一致，避免每次 yaw 更新都重复写 pitch 目标。
- UI pitch 上限 40°，有符号路径推进；仅接收包含两轴八项 PI 的 validated 配置。配置缺失时可正常启动，显示整定未验收并用原 SDK 默认 PI；无效配置拒绝启动。
- SDK 0.2.1 的默认 PI 全部不变。新 API 和使用方法见 `docs/SDK使用说明.md`；新 whl 仅包含电机 SDK 和跟随层。
